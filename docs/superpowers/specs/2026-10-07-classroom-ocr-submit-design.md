# 클래스룸 손글씨 제출 앱 — 설계

## 목표
- **학생(모바일 우선)**: 과제를 고르고 → 텍스트로 직접 입력하거나 손글씨를 촬영해 OCR → 텍스트를 직접 고친 뒤 → 최종본 제출
- **교사(웹 우선)**: 학생 × 과제 표 한 화면에서 모든 제출물 확인, 전체 다운로드
- 무료, 카드 등록 없음, 우리 학교 Google Workspace 안에서만 사용(내부 앱, 구글 앱 심사 없음)

## 구조

```
PWA (GitHub Pages, 무료)            Google Apps Script (API 실행 파일로 배포)
 ├ 학생 화면: 촬영·편집·제출   ──►   scripts.run (호출한 사용자 본인 권한으로 실행)
 ├ 교사 화면: 학생×과제 표           ├ ocr(image)        → 텍스트
 └ 로그인: Google Identity          ├ listAssignments() / submit(...)
   Services (학교 계정 토큰)         ├ createAssignment(...)  (교사)
                                    └ buildGrid(courseId) / exportSheet(...) (교사)
```

- **PWA에서 GAS를 부르는 방법**: GAS 웹앱(doGet/doPost)이 아니라 **Apps Script API `scripts.run`**으로 호출합니다. googleapis.com 주소라 다른 도메인에서도 호출이 막히지 않고(CORS 지원), 함수가 **호출한 학생·교사 본인 권한**으로 실행돼요. 학생 본인 이름으로 제출해야 하는 클래스룸 규칙과도 맞습니다.
- GAS 프로젝트와 OAuth 클라이언트는 학교 계정으로 만든 같은 Google Cloud 프로젝트에 둡니다. 동의 화면은 "내부".

## OCR (범용)
1. PWA가 사진을 긴 변 1600px 정도의 JPEG로 줄여서 `ocr(base64)`를 호출합니다.
2. GAS가 Drive 고급 서비스로 이미지를 Google 문서로 변환하며 OCR을 돌립니다(`ocrLanguage: 'ko'`). 영어도 함께 인식되는 것을 테스트에서 확인했어요.
3. 만들어진 문서의 텍스트를 읽고 임시 파일을 지운 뒤 텍스트를 돌려줍니다.
- 양식에 맞춘 처리는 하지 않아요. 순서가 엉키거나 첨삭 표시가 섞인 부분은 학생이 편집 화면에서 고칩니다.
- 2026-10-07 테스트 결과: 한글·영어 손글씨 글자 인식은 양호하고, 학생이 쓴 철자를 고치지 않고 그대로 옮깁니다. 여러 줄 순서 뒤섞임과 펜 표시가 섞이는 문제는 편집으로 해결합니다.

## 클래스룸 연동
- **과제 생성**: 교사가 이 앱에서 과제를 만들면 클래스룸 과제로 생성됩니다. 클래스룸 API는 앱이 직접 만든 과제에만 학생 제출물을 붙일 수 있기 때문이에요.
- **학생 제출**: 최종 텍스트로 학생 드라이브에 Google 문서를 만들고(원본 사진 첨부), 제출물에 붙인 뒤 제출(turnIn)합니다.
- **교사 표**: 반 → 학생 목록 × 과제 목록 → 제출물을 읽어 표로 만들고, 칸을 누르면 텍스트가 보입니다. 내보내기는 CSV(엑셀·구글 시트에서 열림). 시트 자동 생성은 필요해지면 추가합니다.
- 클래스룸에서 교사가 직접 만든 과제는 표에 제출 상태만 보여 줍니다.

## 화면
- **확정 디자인 (2026-10-07, 미리보기로 승인)**: 테마 C 옵시디언 에메랄드(블랙 + 에메랄드 포인트), 글꼴 Pretendard.
  - 학생 홈: 인사말·반, 벤토(제출 현황 링 / 미제출 / 다음 마감 D-day), 진행 중·완료 과제 카드(마감일·상태 배지), 하단 촬영 버튼.
  - 학생 과제: 촬영 전 → 글자 읽는 중(스캔 애니메이션, 취소) → 수정(사진 썸네일·삭제·추가, 되돌리기, 사진 보기) → 제출 완료(영수증).
  - 교사: 수업 전환 사이드바, 벤토(전체 제출률 + 지난주 대비 / 미제출 / 최근 제출 / 다음 마감), 학생×과제 표(✓ 제출 · ! 지각 · ↩ 반환 · 미제출, 마감일, 학생 검색, 학생별 제출 수), 제출 내용 패널(원본 사진·텍스트·다음 학생), 새 과제(마감일·수업 선택).
- **디자인 원칙: 간결, 직관. 카드형 / 벤토 그리드 스타일.**
  - 학생: 과제 하나가 카드 하나. 화면마다 주요 행동은 하나만 둔다(촬영 / 제출).
  - 교사: 첫 화면은 벤토 그리드(제출률, 미제출 학생, 최근 제출). 학생×과제 표는 그 안의 큰 카드 하나이고, 열 머리글이 과제 바로가기 역할을 겸한다.
  - 장식보다 여백과 정보 위계를 우선한다. 설명 문구는 최소화한다.
- **학생**: 과제 목록 → 과제 화면 하나(위: 촬영 카드와 사진 미리보기, 아래: 텍스트 편집기, 맨 아래: 제출). 직접 입력은 편집기에 바로 쓰면 되고, 여러 장을 촬영하면 텍스트가 이어 붙습니다.
- **교사**: 반 선택 → 학생×과제 표 → 칸 상세 / 과제 만들기 / 내보내기
- PWA 설정: manifest(전체 화면, 아이콘), 오프라인 껍데기용 서비스 워커. 촬영은 `<input type="file" accept="image/*" capture>`
- 학생·교사 화면 모두 PWA가 보여 주고, GAS는 화면을 띄우지 않으므로 GAS 경고 띠가 나오지 않음. 교사는 PC 크롬·엣지에서 "설치"를 누르면 주소창 없는 독립 창으로 사용

## 오류 처리
- OCR 실패나 시간 초과가 나면 직접 입력으로 넘어가고, 사진은 유지합니다.
- 편집 중인 글은 기기에 임시 저장(localStorage)해서 앱을 닫아도 사라지지 않게 합니다. 제출이 성공하면 지웁니다.
- 토큰이 만료되면 조용히 다시 받아 옵니다.

## 의도적인 단순화
- 교사 표는 열 때마다 클래스룸에서 새로 읽습니다. 느리면 GAS 캐시나 시트 캐시를 추가합니다.
- 양식 인식이나 칸별 OCR은 하지 않습니다. 특정 양식이 확정되면 그때 추가합니다.

## 사전 준비 (학교 계정)
- Google Cloud 프로젝트 생성 → Classroom / Drive / Apps Script API 사용 설정 → OAuth 동의 화면 "내부" → 웹 클라이언트 ID 발급
- 필요하면 Workspace 관리자가 이 앱의 접근을 허용

## 테스트
- 실제 휴대폰에서 촬영 → 편집 → 제출하고, 교사 표에 보이는지 확인
- 학교 테스트용 반 하나로 과제 생성부터 제출, 표, 내보내기까지 전체 흐름 확인
